# Stack: AWS serverless

Applies to Lambda, API Gateway, DynamoDB, EventBridge, SQS and Step Functions
services defined with the AWS CDK. Read alongside `AGENTS.md` and
`stacks/typescript.md`.

## Infrastructure as code

- Every resource is defined in CDK. No console-created resources, and no manual
  changes to deployed stacks.
- One stack per deployable service per stage. Stage names come from
  configuration, never from string concatenation scattered through the code.
- Review `cdk diff` before every deploy. A diff that replaces a stateful
  resource (table, bucket, queue) needs an explicit migration plan.
- Stateful resources set `removalPolicy: RETAIN` outside ephemeral stages.

## Lambda

- One handler per function, thin: parse and validate input, call domain code,
  map the result. Domain code has no AWS SDK imports and is unit-testable.
- Set memory and timeout deliberately. The function timeout is shorter than
  the caller's (API Gateway, SQS visibility timeout) so failures surface.
- Initialize SDK clients outside the handler. Reuse connections.
- Structured JSON logs with a request ID or correlation ID on every line.
  Never log secrets, tokens, or full request bodies with personal data.

## Events and queues

- Every SQS consumer has a dead-letter queue and an alarm on its depth.
- Handlers are idempotent: assume every message can arrive more than once.
  Use an idempotency key for side effects that must happen once.
- Use partial batch responses so one bad message doesn't retry the batch.
- EventBridge events have a versioned `detail-type` and a documented schema.

## DynamoDB

- Design keys from the access patterns, written down before the table.
- Conditional writes for anything that must not be overwritten.
- No `Scan` on a request path.

## Security

- Least-privilege IAM generated by CDK grants (`table.grantReadData(fn)`),
  not hand-written wildcard policies.
- Secrets in Secrets Manager or SSM Parameter Store, read at runtime, never
  in environment variables committed to the repo.
- Production accounts and stages are deployed only by the pipeline.

## Observability

- Alarms for errors, throttles, and duration near timeout on every function,
  and for DLQ depth on every queue.
- Tracing enabled across API Gateway, Lambda and downstream calls.
